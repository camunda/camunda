## Resolved: `PartiallyExpandableDataTable` → DS `DataTable` rewrite

Confirmed by the PR 5 implementation ([#63987](https://github.com/camunda/camunda/pull/63987), merged), reused as-is by PR 7 ([#64417](https://github.com/camunda/camunda/pull/64417), merged) and PR 8 ([#64418](https://github.com/camunda/camunda/pull/64418)):

- **DataTable rewrite:** native DS `DataTable` composed with `columns`/`data`/`expansion`, as proposed — no deviation.
- **Pagination replacement:** option (2), not (1). The rewrite keeps scroll-triggered loading via an `IntersectionObserver` watching top/bottom sentinel `div`s rendered below/above the table body, not a manual pageCount:-1/Load-more button. **Deviates from the confirmed option, though:** the observer's `root` is each list's own scrollable wrapper (`overflow-y-auto` on the `ExpandableList` container), not the page's own natural scroll as sanctioned — the double-scrollbar anti-pattern this doc originally flagged is still present, just moved to a fixed-height list rather than wrapping the whole table.
  See [`ExpandableList.tsx`](https://github.com/camunda/camunda/blob/0fac6fac6ec4fe922773c4eb70d00f8e8b352b23/webapp/client/apps/orchestration-cluster-webapp/src/operate/pages/Dashboard/shadcn.components/ExpandableList.tsx#L96-L97) (sentinel refs) and [L180](https://github.com/camunda/camunda/blob/0fac6fac6ec4fe922773c4eb70d00f8e8b352b23/webapp/client/apps/orchestration-cluster-webapp/src/operate/pages/Dashboard/shadcn.components/ExpandableList.tsx#L180) (`IntersectionObserver`).

This closes the sign-off question tracked in [#59208](https://github.com/camunda/camunda/issues/59208) and the third, previously-open acceptance criterion on [#63417](https://github.com/camunda/camunda/issues/63417).

## Resolved: `carbon-compat` for `Tooltip`

Not sanctioned, and not needed. PR 4 ([#63728](https://github.com/camunda/camunda/pull/63728), merged) imports `Tooltip`/`TooltipContent`/`TooltipTrigger` directly from `@camunda/design-system` rather than `carbon-compat/tooltip.js` — see [`InstancesBar.tsx` L9](https://github.com/camunda/camunda/blob/770bd331b8864a51013a753567ab286932dc21e2/webapp/client/apps/orchestration-cluster-webapp/src/operate/components/InstancesBar/shadcn.components/InstancesBar.tsx#L9). The native DS component covered the call site's API needs, so the question of whether `carbon-compat` imports are sanctioned in this codebase never had to be answered for this symbol; it remains open for whichever future PR first has a genuine `carbon-compat`-only gap.
